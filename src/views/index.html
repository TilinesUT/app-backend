Rutas de la API

Referencia rápida de los endpoints disponibles en app-backend, una API construida con Express y TypeScript para administrar usuarios y productos.

Base URL: http://localhost:3000 Express MySQL / MariaDB JSON

Endpoints

Los prefijos se registran en index.ts.

Usuarios

Prefijo /users
GET/users

Obtiene la lista de usuarios.

Respuesta exitosa: { ok, status, res }
POST/users

Crea un usuario después de validar los campos enviados.

Body: name, user, role y password. Roles aceptados: ADMIN, AUDITOR, CLIENT.

Productos

Prefijo /products
GET/products

Obtiene todos los productos.

GET/products/categories

Devuelve las categorías distintas registradas.

GET/products/:id

Busca un producto por su ID.

Ejemplo: /products/12
POST/products

Crea un producto.

Body: title, price, description, category, image, rating_rate y rating_count.
PUT/products

Actualiza un producto usando el id incluido en el body.

Enviar el objeto completo; ver la nota de actualización más abajo.
DELETE/products/:id

Elimina el producto indicado por su ID.

Ejemplo: /products/12

Ejemplo: crear un producto

Envía el JSON en el cuerpo de la petición con Content-Type: application/json.

POST /products
{
  "title": "Teclado mecánico",
  "price": 899.99,
  "description": "Teclado para uso diario",
  "category": "Accesorios",
  "image": "https://ejemplo.com/teclado.jpg",
  "rating_rate": 4,
  "rating_count": 12
}

Cómo se organiza

Una petición entra por Express y pasa por la ruta correspondiente. En las rutas de creación y actualización se valida el body antes de ejecutar el controlador.

Ruta→Validador→Controlador→Modelo→Base de datos
Nota sobre PUT /products

En el código actual, algunos campos del validador de actualización aparecen como opcionales, pero el modelo intenta guardar todos los campos. Para evitar valores faltantes, envía el producto completo junto con su id. Si se quiere editar solo algunos campos, habría que implementar una ruta PATCH que actualice únicamente los campos recibidos.
